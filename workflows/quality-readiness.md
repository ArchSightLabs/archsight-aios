# Quality Readiness 流程

状态：规划基线
适用场景：QA 准入、UAT、试运行确认、领导演示、客户验收前、进入下一环境前、发布前质量门禁

---

## 目标

在真正发布、推送 PR、部署或对外演示前，确认当前交付物是否具备可展示、可验收、可回归和可追责的质量证据。

本流程不是发布动作本身，也不替代 `release` 流程。它回答的是：

- 能不能上 UAT 或试运行环境。
- 能不能给领导、客户或业务专家看。
- 关键路径是否已经验证。
- 缺口、风险和回滚准备是否清楚。

## 角色路由

```text
Mason -> Themis -> Argus -> Hephaestus -> Aegis -> Mason
```

- Mason：确认验证范围、验收目标、环境和交付窗口。
- Themis：承担 QA 责任，设计 UAT、试运行确认、测试策略、验收矩阵、回归覆盖和质量门禁。
- Argus：审查风险、安全、质量缺口和阻断问题。
- Hephaestus：执行测试、脚本、构建、冒烟和修复动作。
- Aegis：确认环境、监控、回滚、事故响应和运行风险。
- Mason：汇总结论，决定是否进入 release / ship / demo。

Themis 和 Aegis 当前是规划角色；在未创建运行时实例前，Themis 的 QA 职责可由 Argus 和 Hephaestus 分担，Aegis 的运行可靠性职责可由 Mason、Hephaestus 和 Argus 分担，但输出必须保留 QA 准入和运行可靠性关注点。

## 输入

- 交付范围和目标环境。
- 面向对象：内部演示、领导评审、客户验收、UAT、试运行确认、生产发布前。
- 需求、PRD、验收标准或演示脚本。
- 变更摘要、风险说明和已知缺口。
- 可运行命令、测试命令、构建命令和回滚方式。

## 输出

- 验收矩阵。
- 验证结果。
- 演示 / UAT / 试运行准入结论。
- 阻断问题和非阻断风险。
- 回滚和应急准备。

## 执行步骤

1. 冻结验证范围：明确本轮要证明什么，不顺手扩大。
2. 定义验收矩阵：核心场景、边界场景、不可接受失败、人工复核点。
3. 准备环境：确认数据、账号、权限、配置、外部依赖和回滚路径。
4. 执行验证：测试、构建、lint、typecheck、冒烟、关键路径人工检查。
5. 风险审查：确认 P0 / P1、权限、安全、数据、性能和回归风险。
6. 形成准入结论：通过、带风险通过、阻断。
7. 记录证据：命令、结果、截图、日志、已知缺口和责任人。

## 验收标准

- 验证范围清晰。
- 验收矩阵覆盖关键路径。
- UAT / 试运行 / 演示所需环境可用。
- 阻断问题已处理或明确停止。
- 已知风险和未验证项被记录。
- 回滚和应急路径明确。

## 禁止事项

- 不把“能打开页面”当作完整验收。
- 不在关键路径未验证时对外演示或进入下一环境。
- 不把缺少测试、缺少数据或缺少权限的问题包装成低风险。
- 不在没有回滚路径时进入高风险发布。
