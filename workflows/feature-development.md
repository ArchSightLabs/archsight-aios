# Feature 开发流程

状态：治理基线  
适用场景：新增明确功能、扩展既有能力、交付可验证业务价值

---

## 目标

用最小可行改动交付用户明确要求的功能，并保证需求、实现、验证和交付记录可追踪。

## 角色路由

```text
Janus / Mason -> Atlas -> Hephaestus -> Argus -> Mason
```

- Janus：确认产品边界和用户价值。
- Mason：拆解任务、定义完成标准。
- Atlas：判断架构影响和边界。
- Hephaestus：执行代码、脚本、文档修改。
- Argus：审查质量、安全、性能和技术债风险。

## 输入

- 用户需求或 PRD。
- 目标项目和影响范围。
- 已知约束、验收标准、不可改动范围。

## 输出

- 最小实现。
- 必要测试或验证记录。
- 变更说明。
- 剩余风险。

## 执行步骤

1. 明确需求、范围和完成标准。
2. 判断是否需要架构审查；若影响边界或数据模型，先交 Atlas。
3. 拆分为可验证的小任务。
4. Hephaestus 执行最小实现。
5. 运行测试、类型检查、lint 或人工验证。
6. Argus 审查风险。
7. Mason 确认交付是否满足完成标准。

## 验收标准

- 功能满足明确需求。
- 没有新增无关功能。
- 没有扩大无关 diff。
- 验证证据完整。
- 已知风险已记录。

## 禁止事项

- 不因“未来可能需要”预埋抽象。
- 不顺手重构无关模块。
- 不在未验证时声称完成。
