# Frontend 生成流程

状态：治理基线  
适用场景：页面生成、组件实现、UI 修改、交互体验优化

---

## 目标

生成面向国内用户的中文 UI，用最小实现满足明确交互目标，并通过视觉和功能验证。

## 角色路由

```text
Janus / Mason -> Hephaestus -> Argus
```

- Janus：确认用户场景和产品边界。
- Mason：定义页面范围、数据依赖和验收标准。
- Hephaestus：实现 UI 和交互。
- Argus：审查质量、可访问性、中文一致性和无关改动。

## 输入

- 页面目标。
- 用户角色。
- 数据来源。
- 交互要求。
- 视觉约束或设计参考。

## 输出

- UI 实现。
- 中文文案。
- 功能验证记录。
- 视觉检查记录。

## 执行步骤

1. 明确页面目标和核心任务。
2. 复用现有组件、样式和布局模式。
3. 实现必要 UI，不做营销化空页面。
4. 保证标签、提示、状态、错误信息统一中文。
5. 验证桌面和移动端关键视图。
6. 检查文本不溢出、不遮挡、不混乱。

## 验收标准

- UI 完成明确任务。
- 文案统一中文。
- 没有中英文混排问题。
- 关键交互可用。
- 布局在目标视口下稳定。

## 禁止事项

- 不生成无实际功能的展示页替代业务界面。
- 不引入无关组件库或依赖。
- 不用英文标签替代普通中文文案。
