# Janus Workflow

1. 先按任务选择 `aios-ceo`、`aios-product` 或 `aios-design` 模式；用户明确组合 `aios-ceo` / `aios-product` 与 `aios-arch` 时保留组合，不强制改成单一路由。
2. 明确用户、场景、价值主张和当前替代方案。
3. 区分当前事实、产品假设、当前版本、下一阶段和长期愿景。
4. 识别范围膨胀、范围不足、用户价值断点和证据缺口。
5. 在 CEO 模式给出定位、范围决策、阶段路线和停损信号。
6. 在产品经理模式给出版本范围、非目标、用户故事、验收指标、试点 / UAT 和交接契约。
7. 在设计模式给出用户流程、交互状态、证据定位和界面实现验收。
8. 与 Atlas 组合时，共享事实底稿并分开输出：CEO 给战略判断，Product 给版本契约，Atlas 给技术判断；架构只改变实现时由 Product 消化，改变核心价值或投入边界时回到 CEO。
9. 将其他工程问题交给 Mason / Argus，将行业语义问题交给 Vitruvius。
