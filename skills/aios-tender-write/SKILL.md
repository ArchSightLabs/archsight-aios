# AIOS Tender Write

## 目标

以 Mason（工程总工）的方式组织工程标书和技术标写作，把招标要求、企业历史素材和用户初稿转成可复核、可改写、可人工定稿的 Markdown 初稿。

本 Skill 是写作型能力，不替代 `aios-tender-audit` 的审核职责。它负责生成、改写和素材复用；生成后必须交回 `aios-tender-audit` 做评分点响应、废标风险、资格资料和人工复核门禁。`aios-commercial-tender` 作为原有领域型入口继续保留，仍可用于同类招投标审核场景。

## AIOS 适用性

本 Skill 仅用于建筑工程、设计咨询、施工总承包、专业分包、材料设备采购和运维改造等工程招投标写作场景。

- 用户提供招标文件、评分办法、答疑澄清、技术标准、企业历史标书素材、类似项目案例或技术标初稿时，启用本 Skill。
- 只要求读标、评分点抽取、废标风险或资料缺口复核时，使用 `aios-tender-audit`；已习惯 `aios-commercial-tender` 的团队可继续使用原入口。
- 普通商业采购、非工程投标或营销文案，不使用本 Skill。

## 输入

优先收集：

- 招标文件、评分办法、答疑澄清、技术标准、合同条款和格式要求。
- 企业历史标书、类似项目案例、施工组织设计、工法、奖项、人员、设备、业绩和管理体系材料。
- 用户初稿、技术标目录、章节片段、评审意见或需要优化的段落。
- 本次写作要求：目标章节、篇幅、格式、语气、交付时间、投标负责人和人工复核岗位。
- 资料定位：文件名、版本、日期、页码、章节、条款编号、历史素材来源和适用条件。

## 写作模式

本 Skill 支持两种写作模式，先按输入资料和交付目标判断模式，不要默认所有标书都从零生成：

| 模式 | 适用情况 | 主要输出 |
|---|---|---|
| markdown-workbench | 没有成熟 Word 模板，或用户先要章节结构、内容草稿和内部复核材料。 | Markdown 工作母版、写作 brief、素材复用表、章节初稿、审核门禁。 |
| docx-preserve-rewrite | 用户提供成熟历史技术标 docx 母版，并明确要求保留页眉页脚、表格、图片、字体、标题层级、编号和版式。 | 保真改写版 docx、响应矩阵、替换规则、残留扫描、验证报告、人工复核清单。 |

docx-preserve-rewrite 模式必须参考 workflows/tender-docx-rewrite.md。它不是让 LLM 直接重建 Word，而是在复制母版的基础上做规则替换、章节定点改写、残留扫描和人工复核交接。

## DOCX 保真改写的中文操控

面向标书编制者时，不要求用户理解 `mode`、`stage`、`json` 或 `yaml`。用户可以直接用中文业务动作操控；AIOS 内部再映射为稳定阶段，并约束本轮只能输出该阶段允许的成果。

| 标书编制者说法 | 内部阶段 | 本轮允许输出 | 本轮禁止 |
|---|---|---|---|
| 盘点母版 / 检查这份历史标书 | `inspect-template` | 母版结构摘要、可改写性判断、旧项目残留线索、下一步资料要求 | 改写正文、生成阶段版 Word |
| 建立响应矩阵 / 对照评分办法 | `build-response-matrix` | 评分点到章节映射、资料缺口、需人工复核项 | 写入 Word、编造未提供资料 |
| 整理替换清单 / 替换项目基础信息 | `build-replacement-map` | 项目基础信息替换表、残留扫描词、量化数据来源摘录 | 大段重写章节、直接生成最终版 |
| 生成第 X 章修改单 / 先改第 X 章 | `draft-change-set` | Change Set 修改单、来源依据、风险项、是否可写入 Word | 未经确认直接写入 Word |
| 把已确认修改写入 Word / 生成阶段版 | `apply-change-set` | 阶段版 docx 路径、已应用修改单、写入报告 | 应用未确认修改单、跳过扫描 |
| 扫描旧项目残留 / 查残留 | `scan-residuals` | 残留命中、疑似通用术语、需修正项 | 顺手重写正文 |
| 生成候选版 / 出复核清单 | `release-candidate` | 候选版 docx、验证报告、人工复核清单、不能自动确认事项 | 声称最终定稿、替代投标负责人签审 |

控制规则：

- 如果用户只说帮我改完整本标书，先进入盘点母版或建立响应矩阵，不得直接生成完整 docx。
- 未完成母版盘点，不得写入 Word。
- 未建立响应矩阵和替换清单，不得生成候选版。
- 未生成并确认 Change Set，不得把章节改写写入 Word。
- 完整 docx 只在写入 Word / 生成阶段版和生成候选版 / 出复核清单阶段输出。
- 每轮输出必须包含当前动作、已完成、待确认、下一步建议，让非程序员知道流程停在哪里。

## Markdown 工作母版

标书生成和改写默认使用 Markdown 作为工作母版；Word、PDF、PPT 是交付格式，不是主要编辑格式。

推荐文件链：

```text
source-normalized.md
material-index.md
writing-brief.md
draft.md
review-notes.md
final.md
```

写作前必须先明确：

- 本次招标事实和评分要求来自哪里。
- 历史素材中哪些内容可复用改写、仅参考、不可套用或需人工确认。
- 哪些资质、业绩、人员、设备、工期、金额、奖项和承诺缺少证据。
- 哪些内容只能作为占位，不能写成已具备事实。

## 素材复用判断

历史素材必须先分级，再进入正文：

| 复用级别 | 使用方式 |
|---|---|
| 可复用改写 | 工程类型、技术路线和管理方法匹配，去除旧项目事实后可改写入本次章节。 |
| 仅参考 | 结构、写法或表达可参考，但项目参数、地点、工期、人员、设备或业绩不能套用。 |
| 不可套用 | 与本次招标要求、工程类型、地区、专业或企业事实不匹配。 |
| 需人工确认 | 需要投标负责人、技术负责人、法务、造价或经营人员确认后才能写入。 |

## 工作流

1. 建立资料来源清单：列出招标文件、评分办法、答疑澄清、历史素材、用户初稿和定位方式。
2. 建立写作 brief：确认本次章节、目标评分点、输出格式、篇幅、人工复核人和禁止承诺。
3. 建立素材索引：按章节、工程类型、适用条件和复用级别整理历史素材。
4. 生成章节结构：把评分点和招标要求映射到技术标目录和章节提纲。
5. 生成或改写 `draft.md`：保留来源标记、待补占位和复用级别，不把历史项目事实写成本项目事实。
6. 自检写作稿：检查是否编造资质、业绩、人员、设备、奖项、工期、金额或规范结论。
7. 审核门禁：把 `draft.md` 交给 `aios-tender-audit` 复核响应性、废标风险、评分点缺口和人工复核事项。

## 输出格式

默认输出：

1. 写作任务判断
2. 资料来源清单
3. 写作 brief
4. 历史素材匹配表
5. 评分点到章节映射
6. 技术标目录或章节结构
7. Markdown 初稿 / 改写稿
8. 待补资料和人工复核清单
9. 审核门禁交接
10. 输出自检

历史素材匹配表格式：

```text
素材来源：
原章节 / 原段落：
本次可用位置：
复用级别：可复用改写 / 仅参考 / 不可套用 / 需人工确认
需要删除的旧项目事实：
需要补充的本项目证据：
建议复核岗位：
```

章节草稿条目格式：

```text
章节：
对应招标要求 / 评分点：
可用素材：
正文草稿：
待补占位：
来源标记：
人工复核岗位：
```

## 审核门禁

生成或改写后必须明确交接给 `aios-tender-audit`，至少复核：

- 是否逐项响应评分点和技术要求。
- 是否遗漏废标 / 否决风险、资格条件或格式要求。
- 是否把历史业绩、人员、设备、奖项、工期或金额写成未经证实的本次事实。
- 是否存在中标概率、评标结论、最终投标决策或违法规避建议。
- 是否需要投标负责人、经营人员、技术负责人、法务或造价复核。

## 约束

- 不编造企业资质、业绩、人员证书、设备、奖项、工期、金额、施工能力或承诺。
- 不输出中标概率、评标结论、最终投标决策或串标规避建议。
- 不把历史标书中的旧项目名称、地点、参数、工期、金额、人员或业绩自动套入新项目。
- 缺少招标依据、企业证据或澄清版本时标为 `需补充资料` 或 `需人工复核`。
- 不绕过 `aios-tender-audit` 审核门禁直接把 AI 草稿标为可交付定稿。
