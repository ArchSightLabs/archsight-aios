# 工程技术标生成与改写基础提示词

## 适用场景

用于基于脱敏招标文件、评分办法、企业历史标书素材、类似项目案例和用户初稿生成或优化技术标目录、章节初稿、评分点响应内容和待补资料清单。

## 使用边界

- 使用 Markdown 作为工作母版，Word / PDF / PPT 只作为后续交付格式。
- 不编造企业资质、业绩、人员、设备、奖项、工期、金额或施工承诺。
- 不输出中标概率、评标结论、最终投标决策或违法规避建议。
- 历史标书素材必须先判断复用级别，不能把旧项目事实自动套入新项目。
- 生成后必须交给 `aios-tender-audit` 做响应性、废标风险、评分点缺口和人工复核门禁；已使用 `aios-commercial-tender` 的团队可继续作为同类审核入口。

## 资料输入区

```text
在这里粘贴脱敏后的招标文件片段、评分办法、技术标要求、历史标书素材、类似项目案例、用户初稿或需要优化的章节。
```

## 提示词

请基于以上资料，辅助生成或优化工程技术标内容。请只使用资料中明确出现的信息；缺少证据的内容写成待补占位，不要补猜。

请按以下结构输出：

### 资料来源清单

| 序号 | 资料名称 / 片段 | 类型 | 版本 / 日期 | 章节 / 页码 / 条款 | 当前用途 | 可信度 / 缺口 |
|---:|---|---|---|---|---|---|

### 一、写作 brief

| 项目 | 内容 |
|---|---|
| 本次写作目标 |  |
| 目标章节 |  |
| 对应评分点 / 招标要求 |  |
| 输出格式 | Markdown 初稿 |
| 人工复核岗位 |  |
| 禁止承诺 | 不编造资质、业绩、人员、设备、工期、金额或中标结论 |

### 二、历史素材匹配表

| 序号 | 素材来源 | 原章节 / 原段落 | 本次可用位置 | 复用级别 | 需删除的旧项目事实 | 需补充的本项目证据 | 建议复核岗位 |
|---:|---|---|---|---|---|---|---|

复用级别只能使用：`可复用改写`、`仅参考`、`不可套用`、`需人工确认`。

### 三、评分点到章节映射

| 序号 | 招标要求 / 评分点 | 原文依据 | 建议响应章节 | 可用素材 | 资料缺口 | 复核岗位 |
|---:|---|---|---|---|---|---|

### 四、技术标目录建议

请生成目录草案，并说明每个章节响应哪些评分点或技术要求。

### 五、章节初稿 / 改写稿

请用 Markdown 输出目标章节初稿。每个章节必须保留：

```text
<!-- 来源：招标文件 / 历史素材 / 用户初稿 / 待补资料 -->
<!-- 待补：缺少的本项目事实或证明材料 -->
```

### 六、待补资料和人工复核清单

| 序号 | 待补内容 | 为什么需要 | 影响章节 | 建议责任人 / 复核岗位 |
|---:|---|---|---|---|

### 七、审核门禁交接

列出需要交给 `aios-tender-audit` 复核的事项：评分点响应、废标风险、资格资料、格式要求、历史素材误套、人工复核岗位。

### 八、输出自检

- 是否使用 Markdown 工作母版。
- 是否包含资料来源、写作 brief、素材复用判断、章节草稿、待补资料、人工复核岗位和审核门禁。
- 是否避免编造资质、业绩、人员、设备、工期、金额或中标结论。
- 是否明确生成后需要 `aios-tender-audit` 复核。
