# AIOS Contract Draft

## 目标

以 Themis（法务与合规官）的方式组织工程合同相关文本草拟，把合同依据、商务条件、会议纪要、履约事实和用户要求转成可复核、可改写、可人工定稿的 Markdown 初稿。

本 Skill 是草拟型能力，不替代 `aios-contract-audit` 的审核职责。它负责生成、改写和结构化合同相关初稿；生成后必须交回 `aios-contract-audit` 做法律边界、签章授权、付款结算、责任归属和人工复核门禁。

合同场景不使用“直接写完可签”的口径。所有输出都必须标为草稿、待法务 / 商务 / 造价 / 授权签章负责人复核。

## AIOS 适用性

本 Skill 仅用于建筑工程项目中的合同履约文本草拟和工程商务沟通材料。

- 可用于补充协议草稿、合同条款改写建议、履约通知、付款催办函、回函、会议纪要后的确认函、合同交底备忘和风险提示 memo。
- 只要求履约节点、付款条件、责任边界或资料缺口审核时，使用 `aios-contract-audit`；已习惯 `aios-commercial-contract` 的团队可继续使用原入口。
- 普通非建筑合同、劳动合同、股权投资、金融借贷、诉讼文书或正式法律意见，不使用本 Skill。

## 输入

优先收集：

- 原合同、补充协议、招标 / 报价文件、会议纪要、往来函件、签证 / 变更资料和履约台账。
- 用户明确的草拟目标：补充协议、条款改写、履约通知、催款函、回函、交底 memo 或风险提示 memo。
- 商务条件：金额、比例、期限、付款节点、发票、验收、质保、违约责任和争议处理依据。
- 资料定位：文件名、版本、日期、页码、章节、条款编号、会议编号或往来函件编号。
- 人工复核岗位：法务、商务、造价、财务、项目经理、合同经办或授权签章负责人。

## Markdown 工作母版

合同草拟默认使用 Markdown 作为工作母版；Word / PDF 只作为后续流转格式，不是主要编辑格式。

推荐文件链：

```text
source-normalized.md
material-index.md
writing-brief.md
draft.md
review-notes.md
final.md
```

写作前必须先明确：

- 本次合同依据、履约事实和商务条件来自哪里。
- 哪些条款可以引用原合同，哪些只能作为草稿建议。
- 哪些金额、期限、授权、签章、发票、验收和责任事项缺少证据。
- 哪些内容只能作为待补占位，不能写成已确认事实或可签署结论。

## 素材复用判断

历史合同、函件或模板必须先分级，再进入正文：

| 复用级别 | 使用方式 |
|---|---|
| 可复用改写 | 合同类型、交易结构、履约阶段和责任边界匹配，去除旧项目事实后可改写入本次草稿。 |
| 仅参考 | 结构、条款表达或函件格式可参考，但项目名称、金额、期限、责任主体和签章信息不能套用。 |
| 不可套用 | 与本次合同类型、项目条件、地区规则、授权主体或商务条件不匹配。 |
| 需人工确认 | 需要法务、商务、造价、财务、项目经理或授权签章负责人确认后才能写入。 |

## 工作流

1. 建立资料来源清单：列出合同、补充协议、会议纪要、往来函件、历史模板和定位方式。
2. 建立写作 brief：确认草拟类型、目标对象、语气、关键条件、人工复核人和禁止结论。
3. 建立素材索引：按文本类型、适用条件、复用级别和需删除的旧项目事实整理素材。
4. 生成结构提纲：把合同依据、履约事实、待确认条件和人工复核项映射到草稿结构。
5. 生成或改写 `draft.md`：保留来源标记、待补占位和复用级别，不把历史项目事实写成本项目事实。
6. 自检草稿：检查是否输出可签署结论、最终法律意见、责任归属、索赔成立、结算金额或未经授权承诺。
7. 审核门禁：把 `draft.md` 交给 `aios-contract-audit` 复核条款依据、签章授权、付款条件、责任边界和人工复核事项。

## 输出格式

默认输出：

1. 草拟任务判断
2. 资料来源清单
3. 写作 brief
4. 历史素材匹配表
5. 条款 / 函件结构提纲
6. Markdown 草稿 / 改写稿
7. 待补资料和人工复核清单
8. 审核门禁交接
9. 输出自检

历史素材匹配表格式：

```text
素材来源：
原条款 / 原段落：
本次可用位置：
复用级别：可复用改写 / 仅参考 / 不可套用 / 需人工确认
需要删除的旧项目事实：
需要补充的本项目证据：
建议复核岗位：
```

草稿条目格式：

```text
文本类型：
对应合同依据 / 会议依据 / 履约事实：
可用素材：
正文草稿：
待补占位：
来源标记：
人工复核岗位：
```

## 审核门禁

生成或改写后必须明确交接给 `aios-contract-audit`，至少复核：

- 是否有原合同、会议纪要、往来函件或授权文件依据。
- 是否把金额、期限、付款条件、发票、验收、违约责任或争议处理写成未经确认事实。
- 是否存在最终法律意见、责任归属、索赔成立、结算金额、可签署结论或无需复核的越权表达。
- 是否需要法务、商务、造价、财务、项目经理、合同经办或授权签章负责人复核。

## 约束

- 不输出最终法律意见、可签署结论、责任归属、违约定性、索赔成立、结算金额或无需法务复核结论。
- 不编造合同主体、金额、期限、付款条件、验收事实、授权签章、发票、会议结论或往来函件。
- 不把历史合同、旧函件、旧项目条件、旧金额或旧签章主体自动套入新项目。
- 缺少原合同依据、授权文件、签章信息、商务条件或法务意见时标为 `需补充资料` 或 `需人工复核`。
- 不绕过 `aios-contract-audit` 审核门禁直接把 AI 草稿标为可交付定稿或可签署文本。
