# 专项施工方案生成与改写基础提示词

## 适用场景

用于基于脱敏施工方案初稿、历史方案素材、工程概况、施工工艺、安全措施、专家意见和用户指定模板生成或优化专项施工方案章节、工艺流程、危险源控制措施和交底要点。

## 使用边界

- 输入资料应先在本地完成脱敏；如包含未授权客户名称、人员姓名、联系方式、证件号码、账号、完整内部原文或其他不应外发资料，先提示用户脱敏或改为摘要，不继续展开实质分析。
- 使用 Markdown 作为工作母版，Word / PDF / PPT 只作为后续交付格式。
- 不输出“方案合格 / 不合格 / 已通过审查”。
- 不替代总工、专家论证、危大工程审批、结构计算、监理、安全负责人或审批主体。
- 不用 LLM 口算承载力、稳定、变形、荷载、设备能力或安全系数。
- 历史方案素材必须先判断复用级别，不能把旧项目事实自动套入新项目。
- 生成后必须交给 `aios-scheme-audit` 做危险源、规范 / 计算书、专家意见和交底要点门禁；已使用 `aios-construction-scheme` 的团队可继续作为同类审核入口。

## 资料输入区

```text
在这里粘贴脱敏后的施工方案初稿、工程概况、施工工艺、安全措施、历史方案素材、专家意见、计算书目录或需要优化的章节。
```

## 提示词

请基于以上资料，辅助生成或优化专项施工方案内容。请只使用资料中明确出现的信息；缺少证据的内容写成待补占位，不要补猜。

请按以下结构输出：

### 资料来源清单

| 序号 | 资料名称 / 片段 | 类型 | 版本 / 日期 | 章节 / 页码 / 图号 | 当前用途 | 可信度 / 缺口 |
|---:|---|---|---|---|---|---|

### 一、写作 brief

| 项目 | 内容 |
|---|---|
| 本次写作目标 |  |
| 目标章节 |  |
| 工程条件 / 专家意见 |  |
| 输出格式 | Markdown 初稿 |
| 人工复核岗位 |  |
| 禁止结论 | 不输出方案合格、计算正确、专家论证通过、审批通过或现场安全满足 |

### 二、历史素材匹配表

| 序号 | 素材来源 | 原章节 / 原段落 | 本次可用位置 | 复用级别 | 需删除的旧项目事实 | 需补充的本项目证据 | 建议复核岗位 |
|---:|---|---|---|---|---|---|---|

复用级别只能使用：`可复用改写`、`仅参考`、`不可套用`、`需人工确认`。

### 三、方案章节结构

请生成方案目录草案，并说明每个章节需要响应哪些工程条件、专家意见、危险源或交底要求。

### 四、方案章节初稿 / 改写稿

请用 Markdown 输出目标章节初稿。每个章节必须保留：

```text
<!-- 来源：方案初稿 / 历史素材 / 专家意见 / 待补资料 -->
<!-- 待补：缺少的本项目事实、图纸、计算书或专业复核结果 -->
```

| 序号 | 危险源 / 控制点 | 已有资料依据 | 建议写入章节 | 待补资料 | 建议复核岗位 |
|---:|---|---|---|---|---|

### 六、待补资料和人工复核清单

| 序号 | 待补内容 | 为什么需要 | 影响章节 | 建议责任人 / 复核岗位 |
|---:|---|---|---|---|

### 七、审核门禁交接

列出需要交给 `aios-scheme-audit` 复核的事项：危险源、控制措施、规范依据、计算书缺口、专家意见回查、交底要点、历史方案误套和人工复核岗位。

### 八、输出自检

- 是否使用 Markdown 工作母版。
- 是否包含资料来源、写作 brief、素材复用判断、方案章节草稿、待补资料、人工复核岗位和审核门禁。
- 是否避免输出方案合格、计算正确、专家论证通过、审批通过或现场安全满足。
- 是否明确生成后需要 `aios-scheme-audit` 复核。
