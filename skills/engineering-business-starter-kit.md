# 工程业务管理基础技能包

> 状态：基础可用版
> 用途：给施工企业工程资料处理、项目复核辅助、部门工作流整理和后续模板沉淀使用。
> 边界：这是 AIOS Skill 的提示词 / 工作流基础包，不是系统交付承诺，也不替代专业人员签审。

## 目标

工程业务管理基础技能包把 6 个工程业务 Skill 组合成一套可直接使用的最小能力：

- 招投标响应矩阵。
- 合同履约节点。
- 施工日报问题跟踪。
- 会议纪要待办闭环。
- 变更签证资料链。
- 专项施工方案辅助复核。

它适合处理施工企业常见的工程业务资料。目标不是证明 AI 能自动完成工程管理，而是帮助业务人员把资料整理成矩阵、清单、台账和复核问题，让后续人工判断更快、更稳、更可追溯。

## 对外口径

推荐表达：

```text
这是一组基础版工程资料处理技能包，用来把招标文件、合同、日报、会议纪要、签证资料和施工方案整理成可复核的矩阵、清单和台账。它可以帮助业务人员减少重复整理工作，但所有工程、合同、造价、法务、质量安全和审批结论仍由对应负责人复核确认。
```

避免表达：

- 不说“AI 自动审查方案 / 合同 / 标书”。
- 不说“可以直接替代投标、法务、造价、项目经理或总工判断”。
- 不说“已经能接入系统、完成部署或形成企业平台”。
- 不说“保证合规、保证中标、判断责任、判断金额或给出最终结论”。

## 最小输入包

每次使用前，先让使用者补齐以下信息：

| 项目 | 必填内容 |
|---|---|
| 资料类型 | 招标文件 / 合同 / 日报 / 会议纪要 / 签证资料 / 施工方案 |
| 资料来源 | 文件名、版本、日期、页码、章节、图号或会议日期 |
| 当前问题 | 想提取什么、复核什么、追踪什么 |
| 输出用途 | 项目复核 / 会议讨论 / 部门台账 / 模板沉淀 / 后续工作流 |
| 外发边界 | 是否脱敏、是否可上传公网工具、是否仅内部留存 |
| 人工复核人 | 投标负责人 / 法务 / 商务 / 造价 / 项目经理 / 技术负责人 / 总工 |

资料不完整时，Skill 应先输出资料状态判断，不得假装已经完成专业审查。

## 通用运行步骤

1. 选择对应 Skill。
2. 粘贴资料片段和最小输入包。
3. 先生成 `Source Map`，确认资料来源和定位方式。
4. 输出矩阵、清单或台账。
5. 把缺资料、缺责任人、缺期限、缺规范证据和需专业复核事项单独列出。
6. 由人工负责人复核后，再决定是否沉淀为部门模板、提示词或本地智能体工作流。

## 统一输出骨架

基础版场景下，6 个 Skill 都应尽量保持以下结构，便于施工企业内部形成统一使用习惯：

1. 输入类型和资料状态判断。
2. Source Map。
3. 主输出表：响应矩阵 / 履约节点 / 问题台账 / 待办闭环 / 资料链 / 辅助复核清单。
4. 需补充确认事项。
5. 人工复核岗位。
6. 可沉淀为部门模板的字段。
7. 不适用或不能下结论的事项。
8. Arbitration：`Claim / Evidence / Tool Result / Decision`。

## Skill 路由

| 场景 | 使用 Skill | 典型输出 |
|---|---|---|
| 招标文件、评分办法、技术标问题、AI 标书工具复核问题 | `aios-commercial-tender` | 问题回应矩阵、评分点响应矩阵、废标风险占位、资料缺口 |
| 分包合同、采购合同、租赁合同、补充协议 | `aios-commercial-contract` | 合同基本事实、履约节点、付款条件、空白字段核对表 |

| 协调会、专题会、交底会、例会纪要 | `aios-construction-meeting` | 会议结论、待办闭环、责任线索、下次追踪清单 |

## 能力分层

| 层级 | 形态 | 适用阶段 | 不应承诺 |
|---|---|---|---|
| L0 | 单次提示词 | 个人使用、单份资料处理 | 不承诺稳定工作流 |
| L1 | Skill 模板 | 部门内部反复使用 | 不承诺系统接入 |
| L2 | 本地智能体工作流 | 固定资料类型、固定输出表 | 不承诺自动审批 |
| L3 | 系统 / 知识库 / 权限集成 | 后续专项评估和项目建设 | 基础版不直接承诺 |

基础技能包默认只覆盖 L0-L1。进入 L2-L3 前，需要单独评估数据权限、资料质量、人员职责、系统接口、部署成本和维护责任。

## 验收标准

一次基础使用只要满足以下标准，就可以认为 Skill 输出可用于内部讨论：

- 输出能回到原始资料位置。
- 缺失信息被标为 `需补充确认` 或 `Need verify`。
- 工程、合同、造价、法务、财务、质量安全事项保留人工复核岗位。
- 输出是表格、清单或台账，能复制进部门工作流。
- 没有把样例输出写成最终专业结论。

## 使用提醒

- 优先使用脱敏资料；未脱敏项目资料不上传公网 AI 工具。
- 输出先用于内部讨论、资料整理和模板验证，不直接作为正式签审依据。
- 如果资料涉及金额、工期、责任、合规、质量安全、结构计算或法律意见，必须由对应负责人复核。
- 基础版重点看“是否节省整理时间、是否更容易复核、是否能沉淀模板”，不要用单次输出判断系统建设成败。
