# AIOS Tender

## 目标

本 Skill 是工程招投标场景的正式短名入口，用于处理用户只说“用 AIOS 看招标文件 / 技术标 / 投标资料”的情况。

它不直接替代写作或审核 Skill，而是先判断任务意图，再路由：

- 生成、编写、改写、优化技术标章节：使用 `aios-tender-write`。
- 审核、复核、读标、查废标风险、列评分点和资料缺口：使用 `aios-tender-audit`。
- 同时要求“先读标再写”：先用 `aios-tender-audit` 建立响应矩阵，再用 `aios-tender-write` 生成章节，最后交回 `aios-tender-audit` 做审核门禁。

`aios-commercial-tender` 继续保留原有工程商务 / 招投标领域入口含义；面向新用户时，推荐优先记忆 `aios-tender`、`aios-tender-write` 和 `aios-tender-audit` 这一组更短的任务型入口。

## 适用场景

- 招标公告、招标文件、评分办法、技术标准、答疑澄清和投标文件目录。
- 技术标初稿、历史标书素材、类似项目案例和用户要求改写的投标章节。
- AI 生成技术标后的人工检查问题、评分点覆盖检查和废标风险复核。

普通商业采购、非工程投标、营销文案和不含工程语义的文件，不使用本 Skill。

## 路由规则

| 用户意图 | 路由到 | 输出方向 |
|---|---|---|
| 读标、评分点、废标风险、资料缺口、响应性复核 | `aios-tender-audit` | 响应矩阵、风险清单、资料缺口、人工复核岗位 |
| 技术标生成、章节改写、历史素材复用、初稿优化 | `aios-tender-write` | Markdown 工作母版、写作 brief、素材复用表、章节初稿 |
| 先分析招标文件再生成技术标 | `aios-tender-audit` -> `aios-tender-write` -> `aios-tender-audit` | 先建证据矩阵，再写作，再审核 |

## 输出要求

路由判断要简短，但必须说明：

1. 资料类型。
2. 当前任务属于写作、审核还是混合流程。
3. 推荐使用的 Skill。
4. 需要人工复核的岗位。
5. 不能由 AI 直接下结论的事项。

## 约束

- 不输出中标概率、评标结论、最终投标决策或规避监管建议。
- 不把未提供的企业资质、业绩、人员、设备、金额或奖项当作事实。
- 不绕过 `aios-tender-audit` 把 AI 生成稿标成可直接交付定稿。
