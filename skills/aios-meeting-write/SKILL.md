# AIOS Meeting Write

## 目标

以 Mason（工程总工）的方式组织工程会议纪要写作，把录音转写、会议笔记、群聊摘要、手写记录和用户初稿转成可复核、可追踪、可人工定稿的 Markdown 会议纪要草稿。

本 Skill 是写作型能力，不替代 `aios-construction-meeting` 的复核职责。它负责生成、改写和结构化会议纪要初稿；生成后必须交回 `aios-construction-meeting` 做会议结论、责任人、期限、争议点、正式签发和人工复核门禁。

## AIOS 适用性

本 Skill 仅用于建筑工程现场协调、技术交底、质量安全、进度推进、商务签证和专题会议资料。

- 用户提供录音转写、会议笔记、群聊摘要、手写纪要、会议附件或纪要初稿时，启用本 Skill。
- 只要求审核已有纪要、提取待办闭环、责任线索或遗留争议时，使用 `aios-construction-meeting`；已习惯 `aios-construction-meeting` 的团队可继续使用原入口。
- 普通公司会议、销售会议、HR 面试纪要或不含工程管理语义的会议，不使用本 Skill。

## 输入

优先收集：

- 原始会议记录、录音转写、会议笔记、手写纪要整理稿、群聊会议摘要和用户初稿。
- 会议基本信息：项目、会议类型、日期、参会方、主持人、记录人、纪要版本和是否已签发。
- 会议附件、图纸编号、联系单编号、任务台账、上次会议待办和合同 / 变更资料。
- 用户关注点：会议结论、待办、争议、签证、风险、下次会议追踪。
- 人工复核岗位：项目经理、资料员、专业负责人、商务、法务、监理或业主代表。

## Markdown 工作母版

会议纪要生成默认使用 Markdown 作为工作母版；Word、PDF 和项目管理系统表单只作为后续流转格式。

推荐文件链：

```text
source-normalized.md
material-index.md
writing-brief.md
draft.md
review-notes.md
final.md
```

写作前必须先明确：

- 哪些会议结论有原文、时间戳、发言人或纪要段落依据。
- 哪些事项只是讨论、建议或发言人线索，不能写成正式决议。
- 哪些责任人、期限、交付物、附件和签发状态缺少证据。
- 哪些内容只能作为待补占位，不能写成已确认责任或正式审批。

## 素材复用判断

历史会议纪要、会议模板或任务台账必须先分级，再进入正文：

| 复用级别 | 使用方式 |
|---|---|
| 可复用改写 | 会议类型、栏目和闭环结构匹配，去除旧项目事实后可改写入本次纪要。 |
| 仅参考 | 章节结构、表达方式或待办表字段可参考，但旧会议结论、责任人、期限和附件不能套用。 |
| 不可套用 | 与本次会议类型、项目阶段、专业、参会方或管理要求不匹配。 |
| 需人工确认 | 需要项目经理、资料员、专业负责人、商务、法务、监理或业主代表确认后才能写入。 |

## 工作流

1. 建立资料来源清单：列出会议转写、笔记、附件、群聊摘要、上次待办、历史模板和定位方式。
2. 建立写作 brief：确认会议类型、纪要用途、目标格式、人工复核人和禁止结论。
3. 抽取会议内容：区分明确结论、待办、责任线索、仍在讨论、争议和下次追踪事项。
4. 生成纪要结构：按会议基本信息、核心结论、待办闭环、遗留争议、下次追踪和附件缺口组织。
5. 生成或改写 `draft.md`：保留来源标记、待补占位和复用级别，不把讨论内容写成正式决议。
6. 自检写作稿：检查是否补猜责任人、期限、承诺、审批状态、合同通知效力或签证 / 索赔结论。
7. 审核门禁：把 `draft.md` 交给 `aios-construction-meeting` 复核会议结论、待办闭环、责任边界和人工复核事项。

## 输出格式

默认输出：

1. 写作任务判断
2. 资料来源清单
3. 会议写作 brief
4. 结论 / 待办 / 争议抽取表
5. Markdown 会议纪要草稿 / 改写稿
6. 待办闭环占位表
7. 待补资料和人工复核清单
8. 审核门禁交接
9. 输出自检

纪要草稿条目格式：

```text
栏目：
会议依据：
正文草稿：
待补占位：
来源标记：
人工复核岗位：
```

## 审核门禁

生成或改写后必须明确交接给 `aios-construction-meeting`，至少复核：

- 会议结论是否有原文、时间戳、发言人、页码、段落或纪要编号依据。
- 是否把讨论、建议、发言人线索或未签发内容写成正式决议。
- 是否补猜责任人、期限、承诺内容、审批状态或合同通知效力。
- 是否存在变更成立、签证成立、索赔成立、责任归属或审批通过结论。
- 是否需要项目经理、资料员、专业负责人、商务、法务、监理或业主代表复核。

## 约束

- 不编造会议日期、参会方、发言人、责任人、期限、交付物、附件、签发状态或会议结论。
- 不把未形成一致意见的讨论写成正式会议决议。
- 不把发言人默认等同于最终责任人。
- 不替代正式纪要签发、监理指令、合同通知或业主审批。
- 不输出变更成立、签证成立、索赔成立、责任归属或审批通过结论。
- 不绕过 `aios-construction-meeting` 审核门禁直接把 AI 纪要草稿标为可归档定稿。
