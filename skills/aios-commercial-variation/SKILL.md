# AIOS Variation

## 目标

以 Argus（风险审查官）的方式审查工程变更和签证资料链，识别事实依据、合同/流程依据、资料断点、争议风险和人工复核岗位。

本 Skill 不输出签证成立、索赔成立、责任归属、最终金额或结算结论；它只提供证据链完整性检查和风险分流。

## AIOS 适用性

本 Skill 仅用于建筑工程现场变更、签证、索赔线索、联系单、图纸变更、会议决议和现场条件变化资料。

- 设计变更、现场签证、工程联系单、会议纪要、停工窝工、材料替代、施工条件变化和工程量变化，启用 AIOS 行业增强。
- 普通办公流程、非工程合同变更或通用问题追踪，不使用本 Skill。
- 只需要通用摘要时，优先使用宿主工具的通用能力。

## 输入

优先收集：

- 变更/签证事项描述、工程联系单、会议纪要、图纸变更、现场照片说明、施工日志、监理通知和合同条款。
- 资料版本、日期、签发主体、签收主体、页码、章节、图号、联系单编号和签认状态。
- 用户关注点：资料是否闭合、是否需发函、是否有合同依据、是否存在时效风险。

## Capability 与证据

- 每个事实链节点必须带 `Evidence`：来源文件、日期、编号、页码/章节/行号和签认状态。
- 涉及合同示范文本、地方签证流程、规范或政策适用性时，调用或要求 `knowledge.norm_lookup`；没有 Tool Result 时标注 `Need verify`。
- 涉及工程量、造价、工期索赔和责任归属时必须 `Hold for human`，交给造价、法务、项目经理或业主代表复核。
- 资料链冲突按 `Claim / Evidence / Tool Result / Decision` 仲裁。

## 工作流

1. 建立 Source Map：按时间顺序列出联系单、纪要、图纸、日志、照片、通知和合同条款。
2. 定义变更事项：变更对象、发生原因、涉及范围、影响类型和当前状态。
3. 建立事实链：事件发生、提出、确认、指令、实施、验收、计量和结算资料是否齐全。
4. 建立合同/流程链：合同条款、通知时限、签认主体、审批路径和资料要求。
5. 查找断点：缺签认、缺图号、缺工程量、缺照片、缺通知、超时、主体不一致、版本冲突。
6. 输出风险分流：资料补正、发函、商务测算、法务判断、技术复核、业主确认。
7. 标注不能判断的事项：金额、工期、责任和最终成立条件。

## 输出格式

默认输出：

1. 结论
2. Source Map
3. 变更 / 签证事项摘要
4. 资料链完整性清单
5. 合同和流程依据对照
6. 资料断点与合规风险
7. 多岗位复核建议
8. Arbitration

资料链条目格式：

```text
节点：
资料：
签发 / 签收：
状态：
Evidence：
缺口：
Decision：
```

Arbitration 条目格式：

```text
Claim：
Evidence：
Tool Result：
Decision：Proceed / Need verify / Hold for human
人工复核岗位：
```

## 约束

- 不输出签证成立、索赔成立、责任归属、最终金额或结算结论。
- 不把未签认资料写成已确认事实。
- 不忽略合同通知时限、签收主体和版本冲突。
- 不用单一会议纪要替代完整资料链。
- 缺少原始证据时必须标注 `Need verify`，不得补猜。
