# AIOS Router

## 目标

本 Skill 是 ArchSight AIOS 的总入口，用于处理用户没有指定具体 `aios-*` Skill、只要求“用 AIOS / AIOS 技能包 / ArchSight AIOS 分析该文档”的情况。

它不替代各专项 Skill。它的职责是：

1. 判断资料类型和任务意图。
2. 选择最合适的 `aios-*` Skill。
3. 按对应 Skill 的规则输出，或在资料类型不清时先做资料状态判断。
4. 保留证据链、资料缺口、人工复核和不能下结论的边界。

## 触发场景

当用户出现以下表达时，应优先使用本入口：

- 请用 AIOS 技能包分析该文档。
- 请用 AIOS 分析这份资料。
- 用 ArchSight AIOS 看一下这个文件。
- 这个工程资料用 AIOS 跑一下。
- 没有明确写出 `aios-tender`、`aios-contract-audit`、`aios-daily`、`aios-meeting`、`aios-scheme`、`aios-commercial-contract`、`aios-construction-scheme` 等具体 Skill，但任务明显属于建筑工程资料整理、复核、写作、台账或证据链场景。

## 路由规则

1. 先看用户是否明确指定了具体 `aios-*` Skill；如已指定，直接使用该 Skill。
2. 未指定时，根据文件名、标题、正文高频词、表格字段和用户任务判断资料类型。
3. 命中单一高置信场景时，按对应 Skill 的 `SKILL.md` 工作流执行。
4. 同一资料包含多个场景时，先输出资料类型判断，再按主任务路由；必要时列出次级 Skill 作为后续复核建议。
5. 当用户动词是“生成、编写、改写、优化初稿、套用历史素材”时，优先选择写作型 Skill；当用户动词是“审核、复核、检查、抽取风险、列缺口”时，优先选择审核型 Skill。
6. 类型不清时，不要泛泛总结；先输出“资料状态判断”和“需要用户补充的资料类型 / 目标”。
7. 不因为用户说“AIOS”就强行套建筑行业规则；非建筑任务优先说明 AIOS 不适用，并建议使用宿主工具通用能力。

## 输出要求

当用户只说“用 AIOS 分析该文档 / 用 AIOS 技能包看一下”且没有明确要求摘要时，默认输出“标准详版报告”，不是短摘要。路由判断可以简短，但专项分析必须展开到可复核的表格、清单或台账。

标准详版报告必须包括：

1. 资料类型和路由判断。
2. 资料来源清单或资料来源说明。
3. 对应业务 Skill 的主输出表 / 清单 / 台账。
4. 资料缺口和需补充确认事项。
5. 人工复核岗位。
6. 不能由 AI 直接下结论的事项。
7. 输出自检。

如果已路由到专项 Skill，应遵守该 Skill 的输出格式；本 Skill 不要求额外生成一份冗长的路由报告。

最小详度要求：

- 资料足够时，主输出表 / 清单 / 台账不应少于 3 条可定位事项；资料不足时，列出全部可定位事项，并说明不足原因。
- 不得只输出几段概括性文字；必须把关键事项拆成表格、清单或台账字段。
- 输出自检必须逐项确认是否包含资料来源、主分析表 / 清单 / 台账、资料缺口、人工复核岗位、AI 不应下结论事项；缺一项时先补齐再结束。

## 约束

- 不输出最终法律意见、合规结论、安全结论、结构计算结论、结算金额或责任归属。
- 不把资料未提及内容补猜成事实。
- 不把“AIOS 总入口”当作通用万能助手；它只负责路由和行业增强边界。
- 涉及金额、工期、法律责任、质量安全、规范、结构计算、审批或签审时，必须保留 `需核验`、`转人工复核` 或对应专业复核岗位。
- 对结构力学、承载、稳定、变形和安全系数，不得由 LLM 口算；需要 `aios-structural`、项目计算书或确定性工具证据。
