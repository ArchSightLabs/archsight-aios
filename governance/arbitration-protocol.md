# Capability 证据仲裁协议

状态：治理基线草案  
适用范围：ArchSight AIOS 多 Agent 冲突仲裁、工具证据裁决和人工升级

---

## 一、目标

本协议把 AIOS 的多 Agent 协作从“角色意见协商”升级为“证据驱动仲裁”。

核心原则：

> Agent 可以提出判断事项，但不能只凭自然语言推理裁决事实。事实裁决必须回到项目证据、结构化知识、确定性工具或人工授权。

适用场景：

- Atlas、Mason、Vitruvius、Argus、Daedalus、Euclid 等 Agent 对方案产生逻辑冲突。
- 架构建议、工程计划、规范语义、结构计算、安全审查或 Runtime 权限之间存在互相阻断。
- AIOS 需要决定继续执行、回滚、重新评审、收缩范围或升级给人类负责人。

### 评审任务合同

开始取证前先锁定 `对象 / 问题 / 范围 / 权限 / 输出`。评审结论不得越过用户实际问题：发布准备度审查不自动扩写成全盘战略重构，机会分析也不能退化成历史问题复述。

- `只读` 允许读取代码、配置、测试、提交记录和既有运行记录，也允许执行低风险、无外部副作用且与风险匹配的本地检查；不允许修改被评项目、远程状态、生产数据或账户，不启动昂贵或未授权的检查。
- 工作区修改、提交、推送、发布、部署和策略变更分别需要相应授权；建议本身不构成批准。
- 多角色联合评审共用事实底稿、分别给出职责内判断；同一宿主、同一模型或同一会话中的不同角色视角，不得宣称为两个独立复核者。

## 二、证据优先级

仲裁时按以下优先级裁决。低层级证据不能推翻高层级证据，除非高层级证据本身被标记为无效、过期或不适用。

| 等级 | 证据 | 说明 |
| --- | --- | --- |
| L0 | 人类硬约束 | 预算、交付窗口、生产授权、法律责任、商业取舍、签章和最终发布许可。 |
| L1 | 确定性工具返回值 | 测试、构建、lint、schema 校验、安全扫描、结构求解器、规范检查 API。 |
| L2 | 项目事实 | 当前代码、配置、接口契约、数据库迁移、部署脚本、CI、ADR、运行日志。 |
| L3 | 结构化知识库 | GraphRAG、规范条文、版本关系、地区 / 专业适用条件、来源页码和质量状态。 |
| L4 | 专项 Agent 判断 | Atlas 的架构判断、Mason 的交付判断、Vitruvius 的领域判断、Euclid 的建模判断。 |
| L5 | LLM 自然语言推理 | 只能作为假设、解释或建议，不能单独作为阻断或放行依据。 |

工具结果优先，但不得盲信工具结果。L1/L3 证据必须带有输入、版本、适用条件和执行状态；缺失时只能进入 `需核验`。

### 证据记录与适用性

影响发布、商业、架构或投入的事实，至少按以下形式记录：

```text
主张：
来源与位置：
实际完成：读取 / 静态追踪 / 执行命令 / 浏览器验证 / 生产记录 / 人工确认
适用范围：commit / 版本 / 环境 / 时间
缺口或冲突：
```

证据类型必须显式区分：历史文档、当前代码 / 配置、实际命令 / 浏览器结果、指定版本和环境的生产记录、推断 / 假设、未知。以下推理无效：

- 历史版本曾在生产成功，不证明新候选版本已经回归通过；候选版本尚未验证，也不能抹去历史生产事实。
- 文档、文件名、`diff --stat`、字段存在或图示只证明其自身存在，不证明端到端链路正确。
- `quick`、抽样或局部门禁不能被写成完整工程门禁；必须核对实际命令、配置和覆盖范围。
- 仅凭时间新旧不判定证据有效；先核对内容、版本、环境和当前对象是否匹配。

关键结论必须主动寻找至少一个可能推翻它的反证，并记录“已排除 / 仍冲突 / 未取得”。存在冲突时不得挑选最方便的单一证据；先按适用性缩小结论，无法消解则进入 `需核验` 或人工升级。

### 事实状态、优先级与决策边界

先区分 `确认缺陷 / 潜在风险 / 验收缺口 / 基础设施阻塞 / 正常 WIP / 产品机会`，再判断优先级与发布影响。三者不得互相替代：

- 未测试、未部署或仍在开发不自动构成产品缺陷，也不自动升级为 P0/P1。
- 严重级别应由实际影响、可达性、可恢复性、证据强度和当前阶段共同决定。
- `推荐 / 备选 / 探索假设` 与 `已批准决策 / 现行策略` 分开书写；只有 L0 授权或项目既有决策记录能改变策略。
- 数量、文档、公式、测试或通过项只能证明其覆盖范围，不能单独证明产品成熟、专业可信或商业成立。

## 三、判断事项契约

Agent 之间发生冲突时，不能只输出“我不同意”。每个参与方必须把意见转成判断事项：

```text
判断事项：
  编号：
  负责 Agent：
  类型：架构 / 交付 / 行业语义 / 结构 / 安全 / runtime / 商业
  表述：
  证据等级：L0 / L1 / L2 / L3 / L4 / L5
  证据：
  假设：
  需核验：
  是否阻断：是 / 否
  严重级别：P0 / P1 / P2
  请求动作：继续 / 修订 / 收缩 / 停止 / 人工升级
```

判断事项必须明确区分事实、判断、假设和待验证项。没有证据的判断事项默认不具备阻断权。

## 四、冲突分类与主裁决依据

| 冲突类型 | 主裁决依据 | 默认处理 |
| --- | --- | --- |
| 架构冲突 | Atlas + L2 项目事实 + L1 验证工具 | 回到 `architecture-review`。 |
| 交付冲突 | Mason + CI / 测试 / 依赖图 | 收缩范围、重排计划或回到任务拆解。 |
| 行业语义冲突 | Vitruvius + 规范工具 + 结构化知识库 | 不满足适用条件时阻断执行。 |
| 结构计算冲突 | Euclid + Solver / 数值校验 + 单位和边界条件 | 缺少输入或工具失败时不得输出确定结论。 |
| 安全 / 权限冲突 | Argus + 安全扫描 + 权限策略 | 默认阻断，除非人工明确批准。 |
| Runtime 冲突 | Daedalus + Capability 权限 + 上下文策略 | 降权、隔离或重新设计工具调用边界。 |
| 商业 / 范围冲突 | Janus / CEO + L0 人类目标 | 人工裁决或明确阶段性取舍。 |

## 五、状态机

```text
proposed
  -> evidence_required
  -> tool_check
  -> accepted
  -> planned
  -> executed
  -> reviewed
  -> completed
```

异常路径：

```text
tool_check -> rejected -> revise
tool_check -> need_verify -> hold
reviewed -> rejected -> revise
any -> human_escalation
```

阻断规则：

- L1 工具返回 `fail` 且适用条件有效时，必须阻断后续执行或放行。
- L3 规范 / 知识证据缺少版本、来源或适用条件时，不能自动判定合规。
- L4 Agent 判断只能触发复核、重评或工具调用，不能独立推翻 L1/L2/L3。
- L0 人类授权可以覆盖执行路线，但不能把未验证事实改写成已验证事实。

## 六、人工升级条件

以下情况必须升级给人类负责人或项目指定审批人：

- 核心技术栈替换。
- 生产数据模型迁移。
- Runtime 权限扩大。
- 多 Agent 自动执行权限放开。
- 自动发布到生产。
- 法规合规最终判定、结构安全结论或工程签章。
- 商业范围、预算、交付窗口和停损信号的最终取舍。

人工裁决也必须记录证据和约束，不能只记录“老板同意”。

---

## 七、决策记录

每次仲裁必须沉淀为可复核记录。最小字段：

```text
决策记录：
  编号：
  日期：
  冲突：
  判断事项：
  证据：
  工具结果：
  决策：继续 / 修订 / 收缩 / 停止 / 升级人工
  已拒绝方案：
  负责人：
  后续动作：
```

决策记录可以写入 ADR、memory、PR 描述、issue 或项目 `.ai/` 目录，具体位置由项目接入规则决定。

---

## 八、落地要求

- Workflow 面向用户的输出必须包含中文化的 `判断事项 / 证据 / 工具结果 / 处理建议`。
- Skill 需要声明可用 Capability、权限边界和证据契约。
- Runtime Adapter 只负责调用工具和回传证据，不替代 Agent 判断。
- 工具调用失败时必须暴露失败原因、输入摘要和可恢复路径。
- 没有 Capability 实现时，必须标为 `已声明接口` 或 `需核验`，不得伪造工具结果。
