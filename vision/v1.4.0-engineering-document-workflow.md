# v1.4.0 工程文档生成、改写与复核闭环

## 版本定位

v1.4.0 的主线是把 AIOS 从“审核型 Skill”升级为“工程文档生成、改写与复核闭环”。

这不是替换 v1.3.x 已有能力，而是在现有招投标、专项施工方案等审核型 Skill 之上增加写作型能力：

- v1.3.x：读资料 -> 抽取问题 -> 输出矩阵 / 清单 / 台账 -> 人工复核。
- v1.4.0：读资料 / 历史素材 -> 生成或改写初稿 -> 响应性检查 -> 风险复核 -> 人工定稿。

现有审核型 Skill 继续作为质量门禁；新增写作型 Skill 负责初稿生成、历史素材复用和章节优化。

## 目标用户与场景

优先服务施工企业、咨询团队和工程资料团队的两类高频写作场景：

1. 标书编写与优化：用户提供招标文件、评分办法、企业历史标书素材、类似项目案例或技术标初稿，AIOS 辅助生成目录、响应矩阵、章节初稿和优化建议。
2. 专项施工方案编写与优化：用户提供方案初稿、历史方案素材、工程概况、专家意见或用户指定模板，AIOS 辅助生成或改写方案章节、工艺流程、危险源控制措施和交底要点。

本版本不承诺替代投标负责人、技术负责人、总工、专家、法务、造价或审批主体。

## 工作母版

Markdown 是 v1.4.0 的 AIOS 工作母版；Word、PDF、PPT 是交付格式，不是主要编辑格式。

推荐文档链路：

```text
原始资料
-> source-normalized.md
-> material-index.md
-> writing-brief.md
-> draft.md
-> review-notes.md
-> final.md
```

各文件职责：

| 文件 | 作用 |
|---|---|
| `source-normalized.md` | 把招标文件、方案初稿、历史素材、专家意见等归一化为 Markdown。 |
| `material-index.md` | 建立历史素材索引，区分可复用、仅参考、不可套用和需核验内容。 |
| `writing-brief.md` | 记录本次写作目标、输出格式、资料边界、人工复核人和禁止承诺。 |
| `draft.md` | AI 生成或改写的章节初稿，保留来源标记和待补占位。 |
| `review-notes.md` | 由审核型 Skill 输出响应性、证据链、风险、缺口和人工复核意见。 |
| `final.md` | 人工定稿前的 Markdown 版本，用于导出 Word / PDF / PPT。 |

## 新增 Skill 分层

### `aios-tender-write`

用途：工程标书、技术标和评分点响应材料的生成与优化。

输入：

- 招标文件、评分办法、答疑澄清和技术标准。
- 企业历史标书素材、业绩材料、人员证书、设备材料和类似项目案例。
- 用户提供的技术标初稿、目录或章节片段。
- 本次写作要求、章节模板和提交格式。

输出：

- 技术标目录建议。
- 评分点逐项响应矩阵。
- 章节初稿或改写稿。
- 历史素材匹配表。
- 缺资料清单和人工复核清单。

边界：

- 不编造企业资质、业绩、人员证书、设备、奖项、工期、金额或承诺。
- 不输出中标概率、评标结论、最终投标决策或规避监管建议。
- 缺少招标依据、企业证据或澄清版本时标为 `需补充资料` 或 `需人工复核`。

审核门禁：

- 生成后必须交给 `aios-commercial-tender` 做响应性、废标风险、评分点和资料缺口复核。

### `aios-scheme-write`

用途：专项施工方案、施工技术措施和交底材料的生成与优化。

输入：

- 方案初稿、工程概况、施工工艺、图纸说明、专家意见和审批意见。
- 历史专项方案、企业工法、标准化章节和用户指定模板。
- 本次项目条件、危险性较大分部分项工程属性和地方要求。

输出：

- 方案章节结构。
- 章节初稿或改写稿。
- 工艺流程和质量安全控制点。
- 危险源与控制措施表。
- 专家意见回查表、计算书缺口和交底要点。

边界：

- 不输出“方案合格 / 不合格 / 已通过审查”。
- 不替代总工、专家论证、危大工程审批、结构计算或安全验收。
- 不用 LLM 口算承载力、稳定、变形、荷载、设备能力或安全系数。
- 计算和规范结论缺少项目计算书、确定性工具或正式依据时标为 `需核验`。

审核门禁：

- 生成后必须交给 `aios-construction-scheme` 做危险源、规范 / 计算书、专家复核和交底要点复核。

## 素材复用工作流

写作型 Skill 必须先做素材治理，再生成正文：

1. 建立素材清单：记录历史方案 / 标书来源、项目类型、专业、章节、日期、适用条件和脱敏状态。
2. 做复用判断：把素材分为 `可复用改写`、`仅参考`、`不可套用`、`需人工确认`。
3. 建立写作 brief：确认本次工程事实、招标要求、输出用途、格式、外发边界和人工复核岗位。
4. 生成或改写初稿：使用 Markdown，保留来源标记和待补占位，不把历史项目事实写成本项目事实。
5. 执行审核门禁：用现有审核型 Skill 检查响应性、证据链、越权结论、缺资料和人工复核事项。
6. 人工定稿：由投标负责人、技术负责人、总工、法务、造价或资料负责人确认后导出交付格式。

## P0 / P1 / P2 开发路径

### P0：写作闭环规格和评测门禁

范围：

- 新增工程文档写作工作流规格。
- 定义 Markdown 工作母版文件链。
- 定义 `aios-tender-write` 和 `aios-scheme-write` 的输入、输出、边界和审核门禁。
- 扩展评测 fixtures，使其覆盖“初稿 + 历史素材 + 写作 brief + 审核门禁”。

验收：

- 规划文档说明写作型 Skill 与审核型 Skill 不冲突。
- 每个写作场景都有至少 1 个脱敏 fixture。
- 评测能检查禁止编造资质、业绩、人员、工期、金额、方案合格和结构安全结论。

### P1：新增写作型 Skill 基础版

范围：

- 新增 `aios-tender-write`。
- 新增 `aios-scheme-write`。
- 为两类 Skill 增加 `agents/openai.yaml`。
- 更新 `skills/README.md`、`runtime/archsight-aios.manifest.json` 和路由说明。
- 补充 basic prompt 和公开脱敏样例。

验收：

- `npm run validate:skills` 通过。
- `npm run validate:prompts` 通过。
- 生成型输出必须包含素材来源、复用判断、待补占位、人工复核岗位和审核门禁说明。

### P1：Markdown 文档工作区模板

范围：

- 新增写作项目目录模板，例如 `templates/document-writing/`。
- 提供 `source-normalized.md`、`material-index.md`、`writing-brief.md`、`draft.md`、`review-notes.md`、`final.md` 的字段模板。
- 说明如何从 Word / PDF / Excel / 历史素材归一化到 Markdown。

验收：

- 模板能支持标书和方案两类场景。
- 每个模板文件都包含资料来源、适用条件、复用边界和人工复核字段。
- 不把交付格式误当作编辑母版。

### P2：真实宿主与试点证据

范围：

- 建立 `skill-runtime` 运行结果归档规范。
- 至少覆盖 Codex 和 WorkBuddy 两个宿主。
- 对同一脱敏输入保存原始输出全文，再做 scorecard 分析。

验收：

- 每个写作 Skill 至少有 1 组真实宿主触发输出。
- 输出能通过结构完整度、证据追溯、边界安全、可执行性和人工复核分流检查。
- 结论只写到当前样本和当前宿主版本，不上升为长期模型优劣判断。

## 禁止事项

- 不把历史方案或历史标书中的旧项目名称、地点、参数、工期、金额、业绩和人员自动套入新项目。
- 不在缺少招标文件、评分办法、工程概况、图纸或计算书时假装已完成专业编写。
- 不输出最终投标决策、方案审批结论、结构安全结论、合规结论、法律意见或结算金额。
- 不把 AI 生成稿直接作为正式交付件；必须保留人工定稿环节。
- 不以新增写作型 Skill 为由削弱现有审核型 Skill 的证据链和人工复核要求。

## 第一实施小步

先落地 P0：补齐规划、测试规格和脱敏 fixture 设计，再进入 `aios-tender-write` / `aios-scheme-write` 的 Skill 实现。

这一步优先，因为它能先锁定写作型能力的边界和验收方式，避免直接生成大段 Prompt 后无法判断是否真的可落地。
