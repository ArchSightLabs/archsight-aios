# ArchSight AIOS 建筑行业技能包自助试用指南

本文面向建筑行业从业者、项目管理人员、技术负责人、资料员、投标人员、方案编制人员和建筑数字化团队，用于自助试用 ArchSight AIOS 技能包。

AIOS 是开源免费的建筑行业 AI 技能包。它的目标不是替代专业人员做最终判断，而是帮助使用者把工程资料整理成可复核的清单、台账、初稿、证据链和人工复核事项。

## 适合试用的人

适合试用：

- 经常处理标书、技术标、专项施工方案、施工日报、会议纪要、变更签证或工程资料的人。
- 希望 AI 输出更贴近建筑行业语境，而不是只给通用总结的人。
- 希望 AI 在输出时明确资料来源、资料缺口、风险提示和人工复核岗位的人。
- 希望把规范摘录、企业标准、审查口径和项目资料整理成 Knowledge Pack 的团队。

不适合直接用来做：

- 最终审图、签审、危大工程审批、结构安全结论。
- 法律意见、造价结算结论、责任归属或投标决策。
- 未经授权的客户资料、完整合同、完整图纸、隐私信息和涉密资料上传。

## 3 分钟安装

如果只是想先试用 WorkBuddy 中的技能包，优先使用下面这条命令：

```bash
npx @archsight/aios@latest install --target workbuddy --scope user
```

安装后可检查一次：

```bash
npx @archsight/aios@latest doctor
```

看到 `Doctor passed.` 表示安装路径、技能包和基础清单可以被找到。

如果希望一次安装到 Codex、Claude Code、OpenCode、Gemini、Antigravity 和 WorkBuddy 等多个工具，可使用：

```bash
npx @archsight/aios@latest install --target all --scope user
```

## WorkBuddy 中怎么使用

安装完成后，打开 WorkBuddy，选择一个普通对话窗口即可。

如果 WorkBuddy 支持技能调用，可直接输入下面的技能名和任务。如果当前工具不支持显式技能调用，也可以把技能名作为普通文字写在第一句，AIOS 会尽量按对应能力执行。

## 推荐先复制的 3 句话

### 1. 标书 / 技术标审核

```text
$aios-tender-audit 请按建筑工程投标文件准备视角，复核以下招标文件或技术标要求，输出评分点响应矩阵、废标风险、资料缺口和人工复核岗位。
```

已习惯旧命令的团队，也可以继续使用：

```text
$aios-commercial-tender 请复核以下招标文件或技术标要求，输出评分点响应矩阵、废标风险、资料缺口和人工复核岗位。
```

### 2. 标书 / 技术标写作

```text
$aios-tender-write 请基于以下招标要求、评分点和历史素材，生成技术标章节 Markdown 初稿，并保留资料来源、待补资料、素材复用判断和审核门禁。
```

### 3. 专项施工方案复核

```text
$aios-scheme-audit 请按 AI 辅助施工方案复核口径，复核以下专项施工方案，输出工程概况、关键工序、危险源、计算书缺口、专家意见回查和人工复核岗位。
```

已习惯旧命令的团队，也可以继续使用：

```text
$aios-construction-scheme 请按 AI 辅助施工方案复核口径，复核以下专项施工方案，输出工程概况、关键工序、危险源、计算书缺口、专家意见回查和人工复核岗位。
```

### 也可以直接试合同、日报和会议纪要

```text
$aios-contract-audit 请复核以下工程合同或补充协议片段，输出履约节点、付款条件、责任边界、资料缺口和人工复核岗位。
```

```text
$aios-daily-write 请基于以下现场口述、项目群记录或照片说明，生成施工日报 Markdown 草稿，并保留资料来源、待补资料和 aios-construction-daily 审核门禁。
```

```text
$aios-meeting-write 请基于以下会议记录或录音转写摘要，生成工程会议纪要 Markdown 草稿，并保留待办、责任线索、待补资料和 aios-construction-meeting 审核门禁。
```

## 第一次建议拿什么资料试

第一次试用不建议直接放完整项目资料。建议从脱敏、局部、低风险资料开始：

| 试用场景 | 建议输入 | 推荐技能 |
|---|---|---|
| 技术标复核 | 招标文件中的评分办法、技术标要求、格式要求，截取 2-5 页即可 | `aios-tender-audit` |
| 技术标写作 | 一个章节要求、评分点、企业历史素材中的脱敏段落 | `aios-tender-write` |
| 合同审核 | 合同或补充协议中的付款、履约、违约、争议条款片段 | `aios-contract-audit` |
| 合同草拟 | 原合同依据、会议结论、草拟目标和需要人工确认的商务条件 | `aios-contract-draft` |
| 方案复核 | 专项施工方案中的工程概况、施工工艺、安全措施、专家意见片段 | `aios-scheme-audit` |
| 方案写作 | 方案目录、工程概况、历史方案脱敏段落、专家修改意见 | `aios-scheme-write` |
| 施工日报生成 | 一天的现场口述、项目群记录、照片说明和材料机械劳务信息 | `aios-daily-write` |
| 施工日报复核 | 一天或一周的脱敏施工日报、现场问题和问题跟踪记录 | `aios-construction-daily` |
| 会议纪要生成 | 一次例会或专题会的录音转写摘要、会议笔记或群聊摘要 | `aios-meeting-write` |
| 会议纪要复核 | 一次例会或专题会的脱敏纪要、待办、责任人和期限 | `aios-construction-meeting` |
| 变更签证资料链 | 脱敏联系单、会议纪要、图纸变更说明和现场记录片段 | `aios-commercial-variation` |

如果只是想体验能力，输入一小段资料即可。AIOS 更看重“资料来源、版本、页码、章节、人工复核点”是否清楚，而不是资料越多越好。

## 不建议上传的资料

除非所在单位已经确认可以使用相应 AI 工具处理这些资料，否则不建议上传：

- 未脱敏的完整合同、完整招标文件、完整图纸、完整投标文件。
- 客户名称、联系人、手机号、身份证、账号、印章、签字页、报价明细。
- 涉及商业秘密、内部报价策略、未公开投标决策、供应商敏感信息的资料。
- 未经授权的规范全文、图集全文、付费数据库内容或第三方版权资料。
- 涉及质量安全事故、法律争议、索赔责任、劳动人事和财务税务的敏感材料。

建议先做脱敏处理：

- 项目名称改成“某项目”。
- 单位名称改成“建设单位 / 施工单位 / 监理单位 / 设计单位”。
- 金额、手机号、身份证号、账号、印章、签字页删除。
- 图纸和规范只摘录必要片段，并保留来源编号，不上传完整受限资料。

## 怎么判断输出是否有用

AIOS 输出不是最终结论。建议按下面清单复核：

| 检查项 | 好输出应当具备 |
|---|---|
| 资料来源 | 能写清资料名称、版本、日期、页码、章节或条款位置 |
| 关键表格 | 有响应矩阵、风险清单、危险源清单、待办台账或复核清单 |
| 资料缺口 | 明确哪些资料缺失，哪些需要补充确认 |
| 人工复核岗位 | 能指出投标负责人、技术负责人、总工、安全负责人、法务、造价或资料员等岗位 |
| 边界意识 | 不直接说合格、不合格、中标概率、计算正确、审批通过 |
| 可继续工作 | 输出能被复制进工作底稿、会议材料、复核记录或部门模板 |

如果输出只有几段泛泛总结，没有资料定位、没有表格、没有资料缺口、没有人工复核岗位，说明这次试用效果不达标。可以换成更明确的技能名，或补充资料来源和目标。

## 推荐的试用顺序

### 试用一：技术标复核

输入材料：

- 招标文件中技术标评分办法。
- 技术标章节要求。
- 已有技术标目录或一段 AI 生成稿。

推荐指令：

```text
$aios-tender-audit 请复核以下技术标资料，重点看评分点响应、废标风险、资料缺口、历史素材误套和人工复核岗位。
```

期望输出：

- 评分点响应矩阵。
- 废标或重大响应风险清单。
- 资料缺口。
- 人工复核岗位。
- AI 不应下结论事项。

### 试用二：技术标写作

输入材料：

- 一个目标章节。
- 对应评分点。
- 企业历史素材中的脱敏段落。
- 本次项目的明确事实。

推荐指令：

```text
$aios-tender-write 请基于以下资料生成技术标章节 Markdown 初稿，保留来源标记、待补占位、历史素材复用判断和 aios-tender-audit 审核门禁。
```

期望输出：

- 写作 brief。
- 历史素材匹配表。
- 章节初稿。
- 待补资料和人工复核清单。
- 审核门禁交接。

### 试用三：专项施工方案复核

输入材料：

- 工程概况。
- 施工工艺或安全措施片段。
- 专家修改意见或计算书目录。

推荐指令：

```text
$aios-scheme-audit 请复核以下专项施工方案资料，重点看危险源、规范依据、计算书缺口、专家意见回查、交底要点和人工复核岗位。
```

期望输出：

- 工程概况与适用范围。
- 关键工序与控制点。
- 危险源与控制措施。
- 规范 / 计算书 / 专家复核清单。
- 班组交底要点。

### 试用四：工程合同审核

输入材料：

- 合同或补充协议中的关键条款片段。
- 用户关心的付款、验收、违约、争议或资料缺口问题。
- 文件名、版本、条款号或页码。

推荐指令：

```text
$aios-contract-audit 请复核以下工程合同资料，重点看履约节点、付款条件、责任边界、空白字段、资料缺口和人工复核岗位。
```

期望输出：

- 合同基本信息。
- 履约节点表。
- 付款与结算条件。
- 责任边界与风险提示。
- AI 不应下结论事项。

### 试用五：施工日报生成

输入材料：

- 当天现场口述或项目群记录。
- 照片说明、材料机械劳务信息。
- 明确的日期、区域、施工部位和资料来源。

推荐指令：

```text
$aios-daily-write 请基于以下资料生成施工日报 Markdown 草稿，保留来源标记、待补占位、事实抽取表和 aios-construction-daily 审核门禁。
```

期望输出：

- 日报写作 brief。
- 事实抽取与待补表。
- 施工日报 Markdown 草稿。
- 问题和风险占位表。
- 审核门禁交接。

### 试用六：工程会议纪要生成

输入材料：

- 会议笔记、录音转写摘要或群聊会议摘要。
- 会议日期、会议类型、参会方或记录人。
- 需要追踪的待办、责任线索和期限。

推荐指令：

```text
$aios-meeting-write 请基于以下资料生成工程会议纪要 Markdown 草稿，保留会议依据、待补占位、待办闭环表和 aios-construction-meeting 审核门禁。
```

期望输出：

- 会议写作 brief。
- 结论 / 待办 / 争议抽取表。
- 会议纪要 Markdown 草稿。
- 待办闭环占位表。
- 审核门禁交接。

## 常见问题

### AIOS 能不能直接判断方案合格？

不能。AIOS 可以列出危险源、交底要点、计算书缺口、专家意见回查事项和人工复核岗位，但不能替代总工、专家论证、审批主体、审图机构或注册人员。

### AIOS 能不能直接判断废标？

不能直接给最终废标结论。AIOS 可以根据招标文件列出疑似废标 / 否决风险和需核验条款，但最终判断应由投标负责人、经营人员、法务或招标代理复核。

### 能不能上传完整规范？

不建议。涉及版权或授权限制的规范、图集、数据库资料，应只使用已获授权的片段、内部整理的条文索引或 Knowledge Pack，并保留来源和版本。

### 输出不够专业怎么办？

优先检查三件事：

1. 是否用了明确技能名，例如 `aios-tender-audit`、`aios-contract-audit`、`aios-daily-write`、`aios-meeting-write` 或 `aios-scheme-audit`。
2. 是否提供了资料来源、版本、页码、章节或条款。
3. 是否说明了本次目标，例如“复核评分点响应”或“回查专家意见”。

### 旧命令还能用吗？

能。`aios-commercial-*` 和 `aios-construction-*` 系列继续保留原有领域型入口。新用户可以优先记忆更短的任务型入口：

- `aios-tender`
- `aios-tender-write`
- `aios-tender-audit`
- `aios-contract-audit`
- `aios-contract-draft`
- `aios-daily`
- `aios-daily-write`
- `aios-meeting`
- `aios-meeting-write`
- `aios-scheme`
- `aios-scheme-write`
- `aios-scheme-audit`

## 责任边界

AIOS 的输出只作为工程资料整理、初稿生成、证据链辅助和人工复核提示，不构成正式法律意见、工程结论、审图结论、安全结论、结构计算结论、造价结论、投标决策或审批意见。

正式交付前，应由对应岗位复核：投标负责人、经营人员、技术负责人、总工、安全负责人、质量负责人、法务、造价、监理、专家或注册人员。
